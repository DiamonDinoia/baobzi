# baobzi MATLAB binding

MATLAB wrapper for the baobzi piecewise-Chebyshev function approximator.

The binding is generated by **mwrap**: [`baobzi.mw`](baobzi.mw) is the single
source of truth, from which mwrap produces the MEX gateway
(`baobzi_mex_gen.cpp`) and the per-function `bz_*.m` stubs. Those generated
files are **committed** (generated-not-hand-edited), so a plain rebuild needs
neither mwrap nor flex/bison. The user-facing [`baobzi.m`](baobzi.m) is a thin
`classdef` that stores the opaque `baobzi_t` handle in its `mwptr` property
(mwrap's R2008OO object-pointer convention).

## Prerequisites

- MATLAB R2019b+ (tested on R2025b)
- `libbaobzi_c.{a,so}` built under `../../build*/` (i.e. `cmake .. && cmake
  --build .` in the repo root)
- `mwrap` — **only** to regenerate after editing `baobzi.mw`. Found on `PATH`,
  or cloned + built automatically by the CMake glue (plain `make`; flex/bison
  are required only to modify mwrap's grammar).

## Build

```bash
# No MATLAB license needed; -static-libstdc++ keeps the .mexa64 independent of
# MATLAB's bundled libstdc++.
make MATLAB_ROOT=/usr/local/MATLAB/R2025b BAOBZI_BUILD=../../build
```

The mex compiles with `-DR2008OO` (selects mwrap's classdef/`mwptr` path).

To regenerate the gateway after editing `baobzi.mw`:

```bash
make mwrap_gen MWRAP=/path/to/mwrap     # or the CMake `regenerate-matlab` target
```

## Usage

```matlab
addpath('/path/to/baobzi/bindings/matlab');

% 1-D scalar fit
f   = @(x) exp(0.5*x(1)) + sin(3*x(1));
obj = baobzi(f, [0], [1], 1e-8);

% Evaluate at N points (N×dim matrix → N×out_dim)
X = linspace(0, 1, 1000)';
Y = obj.eval(X);   % or Y = obj(X)

% 2-D → 3-D vector fit
g   = @(x) [sin(x(1)+x(2)); cos(x(1)-x(2)); x(1)*x(2)];
obj2 = baobzi(g, [-1,-1], [1,1], 1e-6, ...
              'dim', 2, 'out_dim', 3, 'degree', 11, 'max_memory_mib', 64);

[gx, gy] = meshgrid(linspace(-1,1,50));
Y2 = obj2.eval([gx(:), gy(:)]);   % 2500×3

fprintf('Memory: %.1f KiB\n', obj2.memory_usage()/1024);
delete(obj2);
```

## Files

| File | Purpose |
|------|---------|
| `baobzi.mw` | **mwrap source of truth** (inline-C wrappers + trampoline + `@function` decls) |
| `baobzi_mex_gen.cpp` | mwrap-generated MEX gateway (committed; do not hand-edit) |
| `bz_*.m` | mwrap-generated per-function stubs (committed; do not hand-edit) |
| `baobzi.m` | Thin `classdef` over the `bz_*` stubs (handle in `mwptr`) |
| `Makefile` | Builds the mex; `mwrap_gen` regenerates from `baobzi.mw` |
| `run_ctest.cmake` | Bash-free driver for the `matlab_baobzi` CTest |
| `test_baobzi.m` | Smoke/parity tests |
| `examples/` | Simple 1-D, 2-D, vector examples |

## Running tests

```bash
cd bindings/matlab
matlab -batch "addpath('.'); run('test_baobzi.m')"
```

## Trampoline design

`baobzi_fit_f64` accepts a C callback `void f(const double *x, double *y, void *data)` invoked once per Chebyshev sample (synchronously, many times, before returning). To call a MATLAB `function_handle` from inside this callback (the C side receives it via mwrap's `mxArray` pass-through):

1. A `TrampState` struct (file-static scope during the fit call) holds the handle, dimensions, and an error flag.
2. The callback builds a `1×input_dim` mxArray, calls the handle via **`mexCallMATLABWithTrap`** — the Trap variant returns a non-NULL `mxArray*` exception instead of `longjmp`-ing, which would corrupt the C++ baobzi call stack.
3. On exception: stash the mxArray, set `errored=1`, fill `y` with NaN, return. All subsequent callback invocations short-circuit with NaN.
4. After `baobzi_fit_f64` returns: if `errored`, re-raise the stashed message via `mexErrMsgIdAndTxt("baobzi:callback", ...)`. If the fit returned NULL, raise `"baobzi:fit"` with `baobzi_last_error()`.

All of this lives in the `$[ ... $]` inline-C block of `baobzi.mw`.
